## Independent reviews and resolutions

Two independent reviewers (core semantics; Databricks lowering) reviewed the code against the
spec. Findings and resolutions:

| # | Finding | Resolution |
| --- | --- | --- |
| C1 | Integer results declared as `number` outputs failed with OUTPUT_TYPE_MISMATCH | Fixed: conform to output type; regression `review_integer_result_widens_to_number_output` |
| C2 | `coalesce`/`if_else` mixed int/number not widened (distinct counts, false overflow) | Fixed: static-type widening via core typing; `widening_tests` |
| C3 | Label float sum overflow became null/ok | Fixed: `NON_FINITE_RESULT` |
| C4 | Label key types not checked | Fixed: `ENTITY_KEY_TYPE`; null request keys rejected |
| C5 | Label `available_time_column` ignored | Fixed: mismatch is now an error (`LABEL_AVAILABILITY_COLUMN`) |
| C6 | Join errors masked insufficient history differently from the kit | Fixed: transform stages skipped when coverage is not established; sources still reconstructed; regression test |
| C7 | Tenant-join check relies on identical column names | **Fixed** (follow-up): tenant columns derived from the tenant key's `group_by` mapping and join key pairs; metamorphic test renames the dimension tenant column to `org_id`. Residual limit: pairing the tenant with a non-tenant dimension column of the same type is undetectable without column-level tenant metadata |
| C8 | Recency could use a non-window column | Fixed: `RECENCY_EVENT_TIME` |
| C9 | Range checks via lossy i64→f64 | Fixed: exact comparison |
| C10 | `%YAML` directive accepted; `1e-400` underflow | Fixed: `PARSE_DIRECTIVE`, `PARSE_NUMBER_RANGE` |
| D1 | Divide null-vs-zero order and eager/lazy null operands differed | Fixed: core is left-to-right null short-circuit for binary ops; SQL divide tests nulls before zero |
| D2 | Replay could claim visibility before the API served rows | Fixed by protocol: source-as-known reads serve committed snapshots with pending evidence; `published_at` = MERGE commit instant; replay requires recorded evidence |
| D3 | Lazy views re-read live sources between assertions and MERGE | Fixed: host pins each source with `VERSION AS OF` at prepare time and records versions |
| D4 | Reduce-stage assertions not population-scoped; ran for degraded features | Fixed: population semi-join; per-feature tags skipped for degraded variants |
| D5 | Number sum/avg could publish Infinity | Fixed: finite guard |
| D6 | BIGINT sum intermediate overflow | Fixed: DECIMAL(38,0) accumulation + checked cast |
| D7 | Retry/evidence lookup by materialization id fragile | Fixed: lookup existing publication rows and MERGE commits only |
| D8 | Existing table of another version accepted | Fixed: `SHOW TBLPROPERTIES` identity check before MERGE |
| D9 | Positional `IN` in consumer read | Fixed: named columns |
| D10 | Commit timestamp string timezone | Fixed: `unix_micros` round trip |
| D11 | Unavailable population / stale views in reused sessions | Fixed: fail fast `SOURCE_UNAVAILABLE`; drop `fl_*` temp views at prepare |
| D12 | View-name collisions after sanitizing ids | Fixed: generation error |
| D13 | First-reported code may differ from the core when several violations co-occur | **Fixed** (follow-up): one canonical precedence in both engines (see `DECISIONS.md` D8); harness requires Spark's first code to equal the expected code; two multi-violation differential tests |
