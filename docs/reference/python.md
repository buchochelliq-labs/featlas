# Python API

**In plain terms:** the `featlas` Python package is the Rust core loaded into Python. A
`Project` holds the exact bytes of a project file; each method returns the same JSON (as Python
dicts) that the CLI prints. The `featlas_databricks` package uses it to run generated
statements in a Spark session, and `featlas_reverse` uses it to turn legacy feature tables into
specs.

All packages ship in one wheel (`python/pyproject.toml`: `featlas`, module
`featlas._native` built by maturin from `crates/featlas-py`, plus `python-packages =
["featlas_databricks", "featlas_reverse"]`). Requires CPython ≥ 3.12 (abi3). No runtime dependencies; extras
`databricks` (`databricks-sdk`, `databricks-connect`, unpinned), `local` (`pyspark==4.0.1`,
`delta-spark==4.0.0`), `test` (`pytest`, `PyYAML==6.0.3`), `reverse` (`sqlglot==30.30.0`,
`PyYAML==6.0.3`).

## `featlas`

```python
from featlas import Project, FeatlasError, validate, CORE_VERSION, API_SCHEMA, SPEC_VERSION
```

| Name | Value on this commit |
| --- | --- |
| `CORE_VERSION` | `0.1.0` |
| `API_SCHEMA` | `featlas.api/v1` |
| `SPEC_VERSION` | `0.2.0` |

### `validate(document, format="yaml") -> dict`

Staged validation report for `bytes` or `str`; never raises for an invalid document.

### `class Project(document, format="yaml")`

Constructing a `Project` validates the document (parse, schema, references). If it fails, it
raises `FeatlasError("DOCUMENT_INVALID", …)` with the staged report as `detail`.

| Attribute | Meaning |
| --- | --- |
| `document` | The exact bytes (a `str` is UTF-8 encoded) |
| `format` | `"yaml"` or `"json"` |
| `validation` | The full validation report |
| `file_sha256` | SHA-256 of the exact bytes (equals the CLI's) |
| `logical_identities` | Logical fingerprints (as `fe-spec hash` → `logical`) |

`Project.from_path(path)` reads the file as bytes; the format is `json` if the name ends in
`.json`, otherwise `yaml`.

| Method | Returns (API result unless noted) | CLI equivalent |
| --- | --- | --- |
| `hash()` | identities | `hash` |
| `explain(feature)` | feature explanation | `explain --format json` |
| `plan(deployment)` | `plan`, `checks`, `diagnostics`, `plannable`, `execution_ready`, `execution_scope` — does **not** raise when not plannable | `plan` |
| `capabilities(deployment, assessed_at=None)` | capability report | `capabilities` |
| `check_report(report: dict)` | `consistent`, `diagnostics`, `scope` | `check-report` |
| `run_fixtures(suite=None)` | `summary` with per-case results | `test --format json` |
| `evaluate_case(case_id)` | the case result (`["result"]` of the API) | `evaluate` |
| `coverage(deployment, feature_set, as_of, statuses)` | per-feature `{coverage_state, policy, variant}` (`["features"]`) | `coverage` |
| `generate(deployment, generated_at=None)` | in memory: `files` (path → content), `artifacts`, `label_artifacts`, `manifest`, `plan`, `capability_report`, `diagnostics` | `generate` (which also writes files) |
| `consume(request, records=None)` | consumer response (`["response"]`) | `consume` |
| `migration_plan(from_deployment, to_deployment)` | migration plan | `migration-plan` |
| `labels(consumer, label_input)` | label dataset (`["dataset"]`) | `label` |
| `label_requests(consumer, rows, source_status)` | eligible and excluded label requests, no label data read (`["requests"]`) | — |

Example (run from the repository root on this commit):

```python
>>> from featlas import Project
>>> p = Project.from_path("projects/01_fault_count.yaml")
>>> sorted(p.generate("fault_prod")["files"])
['capability-report.json', 'databricks/device_reliability/artifacts.json', 'databricks/device_reliability/script.sql', 'plan.json', 'planning-diagnostics.json']
>>> p.evaluate_case("event_window_edges")["status"]
'passed'
>>> Project.from_path("spec/feature-engineering-spec-v0.2.0/examples/01_fault_count.yaml").plan("fault_prod")["plannable"]
False
```

### `FeatlasError(code, message, detail)`

Raised for every core failure, with a stable `code`, a `message` and structured `detail`
(parsed JSON). The native module raises `featlas._native.FeatlasError(code, message,
detail_json)`, which the wrapper converts.

```python
>>> Project(b"spec_version: 0.2.0\nkind: yes\n")
Traceback (most recent call last):
  ...
featlas.FeatlasError: DOCUMENT_INVALID: The project did not pass parse, schema and reference validation
```

### Guarantees

* All semantics live in Rust; the module only converts between Python objects and JSON
  (`python/featlas/__init__.py`).
* Documents cross the boundary as exact bytes, so `file_sha256` matches the CLI.
* The GIL is released while the core runs (`py.detach` in `crates/featlas-py/src/lib.rs`).
* Nothing reads files named inside documents, fetches URIs, deploys or publishes.

## `featlas_databricks`

A thin host: it executes statements generated by the Rust Databricks adapter in a Spark session
the caller provides and returns physical records to the core. It has no temporal, typing, null
or selection rules of its own.

```python
from featlas_databricks import (
    Core, CoreError, FeatlasError, map_spark_exception, PublicationAuthorization, SnapshotRun,
)
```

### `Core`

A path-oriented facade over `featlas.Project` (projects cached by resolved path):
`project(path)`, `generate(project, deployment, out_dir=None)` (returns `artifacts`,
`label_artifacts`, `manifest`, `plan`; writes files when `out_dir` is given), `labels(project,
consumer, label_input)`, `label_requests(project, consumer, rows, source_status)`, `coverage(project, deployment, feature_set, as_of,
statuses)`, `consume(project, request, records)` (returns `{"response": …}` or
`{"error": {code, message, detail}}`), `evaluate_case(project, case_id)`. Core failures become
`CoreError(message, code, detail)`.

### `SnapshotRun`

```python
SnapshotRun(spark, artifacts, as_of, coverage,
            unavailable_sources=set(), source_relations=None, population_source=None)
```

| Method | Does |
| --- | --- |
| `prepare()` | Population availability check, stale-view cleanup, session settings, source binding (pinned `VERSION AS OF` on real tables, or `source_relations` overrides), reconstruction views |
| `execute()` | Assertions and feature views in canonical order (DECISIONS D8) |
| `materialize(publication)` | Snapshot view, collected as a list of dicts |
| `run_to_snapshot(publication)` | `prepare` → `execute` → `materialize` |
| `publish(auth)` | The only writer: identity check, retry lookup, one `MERGE`, change-data-feed evidence, `published_at` update; returns an evidence dict |
| `preflight_sources()` | `DESCRIBE TABLE` vs `expected_source_schemas`; returns a list of problems |

Attributes `log` (statement names and parameter names), `source_versions` (Delta versions
pinned per source) and `quality_warnings` (warning findings of the last `execute()`, in the core's
`QualityFinding` shape plus `state`). Full behaviour: [Databricks guide](../guides/databricks.md#the-host-runner).

### `featlas_databricks.labels.LabelRun`

```python
LabelRun(spark, label_artifacts, requests, source_relations=None).run() -> dict
```

A `SnapshotRun` over label artifacts: `requests` is the result of `label_requests`; `run()`
registers the eligible requests, reconstructs the label source per distinct dataset cutoff, reads
the values query and returns the core's `LabelDataset` shape, raising the first row failure in
request order ([Labels](../concepts/labels.md)).

### `PublicationAuthorization`

```python
PublicationAuthorization(environment, approved_by, allow_create_table=False,
                         publication_id="", publication_sequence=0, materialization_id="")
```

Explicit, per-run authorization. `publish` refuses (`PUBLICATION_NOT_AUTHORIZED`) unless
`environment`, `approved_by`, `publication_id` and `materialization_id` are non-empty.

### Errors: `featlas_databricks.FeatlasError` and `map_spark_exception`

The host's own `FeatlasError(code, message, rule="", detail=None)` (distinct from
`featlas.FeatlasError`) carries stable codes. `map_spark_exception(exc)` maps a Spark failure:
a `FEATLAS:<CODE>: …` message raised by generated `raise_error` becomes that code;
`ARITHMETIC_OVERFLOW` and `CAST_OVERFLOW` → `NUMERIC_OVERFLOW`, `DIVIDE_BY_ZERO` →
`DIVISION_BY_ZERO`, `CAST_INVALID_INPUT` → `INVALID_SOURCE_ROW`; anything else →
`EXECUTION_FAILURE` (`python/featlas_databricks/errors.py`).

### Differential harness: `featlas_databricks.differential`

Used by `python/tests/test_local_spark_differential.py` on local Spark and, in the live workflow,
on Databricks serverless.

* `register_source(spark, name, spec, rows)` loads fixture rows under their **physical** column
  names into a temp view with explicit Spark types (no JVM-side type parsing, so it works over
  Spark Connect); the generated binding then renames them, exercising the source mapping.
* `run_case(spark, core, project, generated, case, consumer_project=None)` runs one acceptance
  case through the generated SQL with coverage from the core and compares the result with the
  goldens **and** with the core evaluator. Diagnostic cases pass only if Spark's first code equals
  the expected code. Replay cases store publications physically, read them with the generated
  `consumer_read` SQL and select with the core consumer API.
* `compare_warnings(spark, core)`: warning findings must match exactly (feature, check, index,
  outcome, keys, value).
* `compare(actual, expected, ty, tol)`: exact for integers and other types; numbers within
  `max(absolute, relative × |expected|)`.
* `utc_process()` sets the process time zone to UTC.

A local Spark session is local evidence only, not Databricks acceptance (module docstring).
